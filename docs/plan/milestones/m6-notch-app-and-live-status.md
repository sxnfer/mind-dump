- [x] Slice 6, the keyboard rule (branch `m6-keyboard-rules`): the capsule has the keyboard only when the user gave it. The rule lives in one place, `IslandModel`: every open says who opened it (`OpenReason`: `user` or `system`), and `hasKeyboard` is "open, and opened by the user". `AppDelegate` only carries it out (`makeKey`, or `resignKey`). A click on the notch calls `openByUser()`, the entry point the global shortcut will call too, and the box has the caret at once, as before. A text drop that fails (backend down, or a 422) opens the capsule with `system`: the text in the box and the reason under it, the window not key, so the app the user is in keeps the keyboard; the glass shows the non-key shade and no caret. A press anywhere inside that waiting capsule claims it (`NotchWindow.sendEvent` sees the press first, `IslandModel.claim()`), and the caret goes to the end of the kept words, so Return retries; a press on the mode button claims it and flips the mode. A waiting capsule ignores clicks in other apps (that click was for the other app, and closing would throw away the words) and closes by a click on the notch. A capsule that has the keyboard and loses it closes like a click elsewhere (words cleared, a streaming answer cancelled): the window's own `didResignKeyNotification` drives it, with `NSWorkspace.didActivateApplicationNotification` as a second signal for another app becoming active. Our own close resigns too, but by then the capsule is closed, so nothing loops. Closed, a pill, a peek and a drop target never hold the keyboard.

- [x] Slice 8, motion tunings (branch `m6-motion`): San asked for morphs with a much more pronounced spring curve and more blur, so the island stops reading as a resize. - [x] Images in any common format (branch `m6-image-formats`, D42). A photo dropped on the notch is saved and described like a PNG, whatever its format or size. The backend now takes GIF and WebP as well as PDF, PNG and JPEG, by their first bytes (migration 012 widens the database check; API 0.9.0), and reads their pixel size from the header with the standard library, so the 8,000-pixel check covers them. The Mac makes every other image fit before upload, with ImageIO (`Capture/ImagePrep.swift`): any image macOS can decode (HEIC, HEIF, TIFF, BMP, a camera's RAW) that is not PNG, JPEG, GIF or WebP becomes a JPEG, upright (the orientation tag is applied, not copied), named `.jpg` (`IMG_0042.HEIC` is saved as `IMG_0042.jpg`); an image over 8,000 pixels on a side or over 7,864,320 bytes (10 MB once base64-encoded) is scaled down, keeping its shape, until both hold. A PNG whose only problem is its pixel size stays a PNG (a screenshot's text stays sharp, and its transparency stays); otherwise the result is a JPEG at quality 0.85, drawn on white in sRGB. An image within the limits in a format Claude reads goes byte for byte. The format is judged from the bytes (ImageIO's own sniffing), so a HEIC renamed `.jpg` is still converted. The same file always gives the same bytes: fixed settings, a fixed quality, and nothing copied from the original (no date, no place, no camera), so the content hash (D34) finds a second drop as "Already saved". The work runs on a detached task away from the main thread; "Saving…" shows if it takes over 0.3 s. While a drag hovers, only the type is looked at: a PDF over 25 MB is still refused, an image never is for its size (what is sent is at most 7.5 MB). A file that ImageIO cannot decode gives the warning pill "Couldn't read the image" and nothing is sent; a file that is neither a PDF nor an image the Mac can open is refused in the target with "Only PDFs and images" (the accepted set is open-ended now, so the words name the kind, not a list). A debug verb, `prepfile <path>`, makes an image's upload twice without sending it and writes both to `tmp/prep/`.
